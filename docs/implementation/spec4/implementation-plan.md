# SPEC-4 Accepted Implementation Plan

## Objective

Implement the source-controlled Whisper quality, terminology, and evidence-grounded local intelligence behavior from SPEC-4 while preserving Candor's no-cloud and fail-closed release posture.

## Claude review disposition

Accepted:

- Put structured grounded output before terminology correction.
- Keep tier policy in a focused Rust module.
- Store tier and language independently.
- Treat model readiness and hash verification as enforcement, not the hardware recommendation alone.
- Keep measured throughput, VRAM, signing, and clean-install claims blocked without evidence.
- Add pharmaceutical mutation tests and reject uncited output.

Adjusted:

- Use the handoff's 8 GB, 16 GB, and 32 GB safety floors, but do not recommend Balanced on any device until a real bundled-asset benchmark passes. Memory alone is never benchmark evidence.
- Detect total memory and CPU count with a pinned cross-platform system-information dependency. Do not infer GPU capability.
- Permit bounded Unicode terminology. A Latin-1 restriction would break multilingual dictionaries.
- Persist approved and rejected correction decisions in an OS-key-encrypted document, not plaintext and not a debug log.
- Use the pharmaceutical terms supplied by SPEC-4 in synthetic tests. No clinical claims or external patient data are needed.
- Keep `main.rs` dispatch thin, but acknowledge that explicit methods must still be registered there.

Rejected:

- Do not add an unverified Qwen digest placeholder that looks like a hash. Candidate metadata can contain a null artifact digest while release selection remains blocked.
- Do not treat Apple Silicon architecture alone as proof of supported acceleration.
- Do not expose a Maximum override that bypasses core hardware and asset guards.

## Phase 1: Candidate locks and package profiles

- Add all Fast, Balanced, and Maximum Whisper candidates with immutable source revision, bytes, SHA-256, license, and intended package profile.
- Add the pinned Qwen Instruct-2507 source revision and official Qwen GGUF fallback metadata.
- Keep both language candidates unselected.
- Add `complete` and `complete-max` profile requirements to the verifier.
- Keep the normal source manifest non-ready and asset-free.

## Phase 2: Persistent transcription quality

- Add `transcription_quality.rs`.
- Persist tier, language preference, and benchmark evidence atomically under core-owned settings storage.
- Run benchmark work through one cancellable allowlisted job. Accept only a product tier from the renderer, generate all workload inputs in the trusted core, reject duplicate active checks, and persist only core-measured evidence tied to verified model fingerprints.
- Collect total memory, logical CPU count, architecture, and OS without invoking a process.
- Expose Fast, Balanced, and Maximum evaluations with guard reasons and model readiness.
- Resolve normal transcription from the persistent tier. Preserve the advanced model override only behind Advanced Settings.
- Never publish an estimated duration until a measured real-time factor exists for the selected model hash.

## Phase 3: Strict grounded local intelligence

- Version internal recap and Ask prompt templates.
- Require strict JSON from the model.
- Parse with bounded serde types and reject unknown or malformed structures.
- Require every supported claim to reference valid transcript segment IDs.
- Reject unsupported owners, dates, dosages, concentrations, drug names, and conclusions.
- Return structured results to Electron while retaining a compatibility Markdown rendering generated by the trusted core.

## Phase 4: Terminology dictionaries

- Add an OS-key-encrypted terminology store with atomic writes and corruption-safe refusal.
- Support bounded dictionary import, enablement, recording assignment, and term selection.
- Build Whisper vocabulary context only from enabled or assigned terms and stay within the existing prompt budget.
- Produce correction proposals with source segment IDs.
- Never auto-apply high-risk or uncertain proposals.
- Persist explicit accept or reject decisions and do not re-propose rejected pairs for the same recording.

## Phase 5: Typed Electron and desktop UI

- Add exact runtime schemas, input limits, preload methods, and renderer parsers.
- Add `AI & Transcription` normal settings with Fast, Balanced, and Maximum only.
- Show recommendation, availability, guard reason, benchmark state, and local readiness.
- Start the Balanced performance check once when verified bundled assets are ready and capture is idle. Offer a retry for failed or cancelled checks and a separate Maximum accuracy check after its memory guard passes.
- Add terminology import and enable controls.
- Keep model IDs, hashes, Q4_K_M, runtime revision, and raw benchmark values in Advanced Diagnostics.
- Remove initial-prompt authoring from the renderer API.
- Show only product labels during a meeting.

## Phase 6: Tests and release gates

- Add Rust policy, corruption, terminology, high-risk mutation, and strict JSON tests.
- Add Electron input, preload-surface, renderer, compact-layout, and accessibility tests.
- Extend source security and bundle-verifier mutation checks.
- Add SPEC-4 acceptance and verification reports.
- Run default and feature-enabled Rust tests, strict clippy, `npm run v3:verify`, package smoke, Playwright, and visual evidence.
- Send the final diff and verification report to Claude for adversarial review.

## Explicitly blocked after source implementation

- Selecting or packaging Qwen3-4B-Instruct-2507 Q4_K_M before reproducible conversion and evaluation.
- Marking the official Qwen3-4B-GGUF fallback as Candor-approved before quality and safety evaluation.
- Claiming measured throughput on 8 GB, 16 GB, or 32 GB systems without real model runs.
- Producing Complete or Complete Max installers without the selected assets.
- Signing, notarization, clean offline installation, upgrade, and long-duration evidence.
- Public beta while strict offline transcription and recap fail the release gate.
